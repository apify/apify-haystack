# Coding guidelines

This file provides guidance to programming agents when working with code in this repository.

[Haystack](https://haystack.deepset.ai/) integration for the [Apify](https://apify.com/) platform, published on PyPI as `apify-haystack`. All components live in `src/apify_haystack/apify_dataset.py`: `ApifyDatasetLoader`, `ApifyDatasetFromActorCall`, and `ApifyDatasetFromTaskCall`.

Read [CONTRIBUTING.md](CONTRIBUTING.md) first. It covers setup, tasks, and tests, and all of it applies to agents too.

@CONTRIBUTING.md

## Components

- Components follow the Haystack 3 lifecycle: the `ApifyClient` is created in `warm_up` (or lazily by `run`) and released in `close`, never in `__init__`. The async side mirrors it with `ApifyClientAsync`, `warm_up_async`, `run_async`, and `close_async`, and `run` and `run_async` keep identical signatures.
- The token is a Haystack `Secret`. Keep `to_dict` and `from_dict` in sync with `__init__` parameters; the mapping function is serialized by its import path.
- Clients come from `_create_client`, which adds the `x-apify-integration-platform` header and the `Origin/haystack` user-agent marker.
- Unit tests mock `ApifyClient` and `ApifyClientAsync` and never call the Apify API.

## Conventions

- Run `uv run poe check-code` before finishing a change.
- Every module starts with `from __future__ import annotations`. Use single quotes, single backticks in docstrings, and ASCII-only source.
- Tests are flat `def test_*()` functions with a one-line docstring. Parametrize with `pytest.param(..., id='...')`, and use `Mock` and `monkeypatch` for test doubles.
- Commits and PR titles follow [Conventional Commits](https://www.conventionalcommits.org/). `feat`, `fix`, `perf`, `refactor`, and `style` trigger a release, so use them for source code changes only. Mark breaking changes with `!`.
