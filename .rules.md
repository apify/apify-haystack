# Coding guidelines

This file provides guidance to programming agents when working with code in this repository.

[Haystack](https://haystack.deepset.ai/) integration for the [Apify](https://apify.com/) platform, published on PyPI as `apify-haystack`. The dataset components (`ApifyDatasetLoader`, `ApifyDatasetFromActorCall`, and `ApifyDatasetFromTaskCall`) live in `src/apify_haystack/apify_dataset.py`, `ApifyWebSearch` in `src/apify_haystack/web_search.py`, and the Agent tool `ApifyActorTool` in `src/apify_haystack/actor_tool.py`. The client base they share is in the private `src/apify_haystack/_client.py`.

Saved pipelines reference classes by their import path, so moving or renaming a public module or class breaks them.

Read [CONTRIBUTING.md](CONTRIBUTING.md) first. It covers setup, tasks, and tests, and all of it applies to agents too.

@CONTRIBUTING.md

## Components

- Components follow the Haystack 3 lifecycle: the `ApifyClient` is created in `warm_up` (or lazily by `run`) and released in `close`, never in `__init__`. The async side mirrors it with `ApifyClientAsync`, `warm_up_async`, `run_async`, and `close_async`, and `run` and `run_async` keep identical signatures.
- The token is a Haystack `Secret`. Keep `to_dict` and `from_dict` in sync with `__init__` parameters; a mapping function is serialized by its import path.
- `ApifyActorTool` is the one exception to the lifecycle: without `parameters`, its `__init__` reads the Actor's input schema with a short-lived client. `to_dict` stores the resolved schema, so `from_dict` makes no API request.
- Clients come from `_create_client` in `_client.py`, which adds the `x-apify-integration-platform` header and the `Origin/haystack` user-agent marker.
- Unit tests mock `ApifyClient` and `ApifyClientAsync` (patched on `apify_haystack._client`) and never call the Apify API.
- Integration tests in `tests/integration` call the real Apify API with the `APIFY_TOKEN` token. Keep Actor runs few and small, prefer deterministic outputs that do not depend on the content of a live page, and delete every resource a test creates.

## Conventions

- Run `uv run poe check-code` before finishing a change.
- Every module starts with `from __future__ import annotations`. Use single quotes, single backticks in docstrings, and ASCII-only source.
- Tests are flat `def test_*()` functions with a one-line docstring. Parametrize with `pytest.param(..., id='...')`, and use `Mock` and `monkeypatch` for test doubles.
- Commits and PR titles follow [Conventional Commits](https://www.conventionalcommits.org/). `feat`, `fix`, `perf`, `refactor`, and `style` trigger a release, so use them for source code changes only. Mark breaking changes with `!`.
